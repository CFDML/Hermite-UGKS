# ugks1d — Unified 1D UGKS + Hermite-spectral force-term solver

A single Fortran source tree that runs three one-dimensional benchmarks of
force-driven multi-scale gas flow from a common UGKS + Hermite-spectral
algorithm. All run parameters are set in **one input file** (`input.namelist`);
no source edit or recompile is needed to change cases, mesh, velocity space,
or quadrature.

Reference paper:
> Shuangqing Liu, Zuoxu Li, Yonghao Zhang, Tianbai Xiao,
> *An efficient solution algorithm for force-driven continuum and rarefied
> flows*, arXiv:2507.10021 (2025).

## Quick start

```bash
make                    # builds ./ugks1d (gfortran)
./ugks1d                # runs with input.namelist (default: case 3, Sod)
./ugks1d myconfig.namelist   # run with a different config file
```

Edit `input.namelist` to switch case, mesh, velocity quadrature, etc.

## Input file (`input.namelist`)

All user-tunable parameters in one Fortran namelist:

| Parameter | Meaning | Default |
|-----------|---------|---------|
| `nx` | number of physical cells | 600 |
| `xlength` | domain length | 1.0 |
| `nv` | number of velocity collocation points | 100 |
| `vmax` | velocity half-width (domain = ±vmax·√Tref) | 5.0 |
| `Tref` | reference temperature for velocity scaling | 1.0 |
| `quad_type` | `'newton_cotes'` or `'gauss_hermite'` | `'newton_cotes'` |
| `force_type` | `'finite_difference'` or `'hermite'` (body-force term) | `'hermite'` |
| `Nm` | Hermite expansion order (only if `force_type='hermite'`) | 6 |
| `cfl` | CFL number | 0.5 |
| `maxtime` | stop time | 0.2 |
| `steady_tol` | fixed-scale primitive residual tolerance (case 4) | 1e-9 |
| `mass_tol` | relative mass-drift tolerance (case 4) | 1e-10 |
| `steady_steps` | required consecutive converged steps (case 4) | 1000 |
| `case_id` | 2=hydrostatic, 3=Sod, 4=Fourier | 3 |
| `knudsen` | reference Knudsen number | 0.01 |
| `phi` | external force acceleration | -1.0 |
| `TwL`, `TwR` | wall temperatures (diffuse BC, case 4) | 1.0, 1.1 |
| `refpfile` | case 2 reference pressure file (optional) | '' |

Hermite/Gauss-Hermite settings used for the three paper checks:

```
case 2 (hydrostatic): nx=600 nv=36 Nm=6  knudsen=1.0  phi=-1.0 maxtime=0.08
case 3 (Sod):         nx=600 nv=34 Nm=6  knudsen=0.01 phi=-1.0 maxtime=0.2
case 4 (Fourier):     nx=800 nv=22 Nm=10 knudsen=0.1  phi=+2.0 maxtime=20
```

The ready-to-run namelists are in `cases/`.

## Cases

| `case_id` | Problem | Initial condition | Boundary | Force `phi` |
|-----------|---------|------------------|----------|-------------|
| 2 | 1D hydrostatic equilibrium (well-balanced) | `ρ=exp(−x)`, `p=exp(−x)+0.01·exp(−100(x−0.5)²)` | specular | −1.0 |
| 3 | Sod shock tube under force | left `(ρ,U,p)=(1,0,1)`, right `(0.125,0,0.1)` | specular | −1.0 |
| 4 | Fourier flow between isothermal plates | `ρ=1`, linear `T` ramp `TwL→TwR` | diffuse wall | +2.0 |

The boundary type is derived automatically from `case_id` (case 4 → diffuse
isothermal wall; cases 2, 3 → specular reflection). The diffuse wall reuses
`calc_flux_boundary` in `flux.f90`, which sets wall density by mass-flux
balance (`prim(1) = −R1/R2`). With the paper's nondimensional convention,
`prim(3) = λ = 1/T`, so a wall at `Tw` is passed `prim(3) = 1/Tw`.

## Velocity quadrature

Two quadratures, selected by `quad_type`:

- **`newton_cotes`** (default): uniform nodes on `[−vmax·√Tref, +vmax·√Tref]`,
  6th-order closed Newton–Cotes weights. Works for any `nv`.
- **`gauss_hermite`**: roots of the physicist's Hermite polynomial `H_nv`,
  weights from Eq.(34) of the paper, generated by a normalized Hermite
  recurrence and Newton iteration with ordered, symmetry-paired roots.
  Supports any `nv ≥ 2`. Nodes are scaled by
  `√Tref`; weights are stored as plain `∫g(v)dv` quadrature weights (the
  `e^{v²}` rescaling is folded in), so the rest of the code is quadrature-
  agnostic.

## Algorithm (common to all cases)

- **Finite-volume UGKS** with the BGK integral solution as the numerical flux
  (paper §3.2, Eq. 12–22). The force-modified particle trajectory
  `x' = x − v'Δt − ½aΔt²`, `v' = v − aΔt` is built into the flux (`flux.f90`).
- **Body-force term** `a·∇ᵥf` (paper §3.3, Eq. 23–28), in `gravity.f90`,
  selected by `force_type`:
  - `'hermite'` (default): Hermite spectral expansion (`cal_fv`), order `Nm`.
    Uses the recurrence `v·Heₙ = Heₙ₊₁ + n·Heₙ₋₁` — no velocity-space stencil.
  - `'finite_difference'`: velocity-space central difference of `f` (`cal_fv1`).
    The classical discrete-velocity approach.
- **Well-balanced** hydrostatic equilibrium (paper §3.5).
- Macroscopic prediction (`aT`, the temporal slope) is done only at interior
  interfaces; boundary interfaces use the distribution-function moments
  directly, so the macroscopic boundary condition emerges implicitly from the
  kinetic boundary flux — no separate macroscopic BC is needed.

## Output

Each run writes `macro<iter>.dat` (Tecplot) with columns
`X, RHO, U, T, P, PERTURBATION, Q, error1, error2, N`:
- `PERTURBATION` = `P − P_ref`. For case 2, `P_ref` is read from `refpfile`
  if present; otherwise the analytic `exp(−x)` is used.
- `T=1/λ`, `P=ρT/2`, consistently with the paper's `R=1/2`
  nondimensionalization.
- `Q` is the physical heat flux of paper Eq.(7), including the factor `1/2`.
- `error1`, `error2`, `N` are Hermite-expansion convergence diagnostics.

Run `python plot_hermite_validation.py` to produce the simple three-panel
comparison in `figures/`. It plots one paper quantity per case: hydrostatic
pressure perturbation, Sod density, and Fourier density.

## Source layout

```
src/
  config.f90          module CONFIG       — all run params + read_config (namelist)
  data1d.f90          module ALLDATA      — derived data types, host-uses CONFIG
  grid.f90            module GRIDMAKER    — structured 1D mesh (nx from CONFIG)
  gastheory.f90       module GASTHEORY    — Maxwellian, moments, tau
  velocity.f90        module VELOCITY     — Newton-Cotes + Gauss-Hermite generators
  gravity.f90         module GSOURCE      — Hermite force term cal_fv
  flux.f90            module FLUX         — UGKS flux + 3 boundary fluxes
  initialization.f90  module INITIALIZER  — case-dependent IC, params from CONFIG
  solver.f90          module SOLVER       — timestep/interp/evolve/update
  output.f90          module OUTPUT       — Tecplot output
  main.f90            program main        — read_config, drives loop
input.namelist                            — the one file users edit
Makefile
README.md
```

Module compile order (enforced by the Makefile):
`config → data1d → grid → gastheory → gravity → velocity → flux →
initialization → solver → output → main`.

## Build

```bash
make                 # GNU Fortran (default)
make clean
make FC=ifort        # Intel Fortran Compiler Classic
```

The Makefile selects the appropriate module and OpenMP options for `gfortran`
or `ifort`. Run `make clean` before switching compilers because their object
and module files are not interchangeable.

## Notes

- The grid is self-generated; no mesh file is needed.
- `knudsen`, `phi`, `maxtime`, etc. are run-time variables (set in
  `input.namelist`), not compile-time parameters.
- Case 2's `origin.dat` reference pressure file is optional; if absent the
  analytic `exp(−x)` profile is used.
